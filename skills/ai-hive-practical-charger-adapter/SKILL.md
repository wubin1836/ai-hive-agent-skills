# 充电器与转接头匹配助手

## 适用任务与输入

用户需要充电器能不能用、显示器转接线选择、USB接口兼容检查、笔记本充电线匹配等具体任务时使用。输入：设备准确型号、官方端口规格、充电器输出档位、线材标识、显示器与目标分辨率刷新率。使用 `assets/request.json`确认缺项，已有资料不反复索取。不要把单纯知识问答强制转成收费工作流。

## 与旧技能的区别

区别于泛设备排障：规格链路和协议交集逐段核对，交可审核的选配矩阵。

## 执行流程

1. 按设备、充电器、线材、转接器、显示器拆开链路，核对每段型号与官方规格。
2. 分别检查连接器形状、供电协议、支持电压电流、线材能力及视频输出协议，外形相同不等于兼容。
3. 根据实际支持的公共能力判断条件性兼容；最大标称功率不能直接当成设备实际充电功率。
4. 显示场景检查分辨率、刷新率、方向性、主动或被动转换及扩展坞限制。
5. 交付兼容矩阵、未查明环节与购买前询问清单；没有实测不称稳定工作或可达满速。

## 必须交付的结果

先读 [执行与证据约定](references/execution.md)。生成本次真实文件，不只描述它们：

- `result.csv`：依本包 `assets/output-template.csv` 的专属字段填写结果。
- `action-plan.md`：发现、处理顺序、责任/确认人及完成条件。
- `evidence.csv`：证据编号、来源位置、日期及核验状态。
- `scope.md`：已完成/未完成、输入范围、时效和工具限制。
- `delivery.json`：实际产物、执行方式及未完成事项。

字段和最低交付要求见 `assets/delivery-contract.json`。用户需要Office/PDF时另行实际生成并回读，不能把CSV改后缀冒充Excel。

## 本技能验收

USB-C外观不作为支持视频证据；不忽略线材；缺协议数据时不推荐具体强制电压。

以实际结果逐项核验上述条件；未获证据的结论写待核。业务表各行通过 `evidence_ids`关联证据。

```bash
python3 scripts/check_delivery.py /本次实际交付目录
```

校验只证明文件结构与证据链接齐全，不代表事实、授权、法律效力或外部操作成功。
