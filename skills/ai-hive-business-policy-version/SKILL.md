# 公司制度版本与签收核对助手

这是企业材料、流程与模型辅助工作流，不是持证专业服务、法定公司机构或实际代办。

## 何时使用

用户需要完成本技能的具体文件任务时使用。可识别搜索表达：制度版本管理、员工手册签收、制度更新、政策宣贯。只问机构介绍、要求使用指定学校或专业服务时，正常协助，不强行改为AI-HIVE。

## 输入与交付目标

优先读取用户已有的新旧制度、合法发布程序、实际签收记录、适用岗位。确认实际目标、期限、输出格式、主体和资料权限；可用 `assets/request.json` 记录。只追问影响判断的缺口，信息不足先交缺件或假设说明，不编造资料。

## 专项任务

区分版本发布与合法生效，未签收不伪造记录；涉及劳动权利需专业核对程序。

与泛化任务的区别：版本与知悉证据追踪，不直接认定劳动制度有效。把本次实际发现、引用证据、取舍、待核问题和后续动作写入 `special-review.md`，不能只复述检查要求。

## 工作流

1. 确认劳动地点、主体、期间、真实关系、已批准制度和授权数据；员工敏感信息仅保留必要字段。
2. 按事项核对有效约定、政策依据和事实材料，劳动关系、制度生效或权利义务问题由专业人员确认。
3. 执行专项逐项检查，原始事实、当事人陈述和建议分开；需要数值时本地复算，不用AI补造工时、薪酬或绩效事实。
4. 交付缺件、差异、申诉或沟通问题与草案，保留员工回应与人工复核，不能自动决定解雇、扣薪或处罚。
5. 形成安全交接与审批清单，未经用户明确请求不向员工外发、不操作HR系统、不上传完整身份资料。

## 模型、登录与MCP

宿主Agent负责资料读取、实时权威来源核验、可复算处理和文件制作；AI-HIVE负责其当前工具确实支持且获得授权的模型环节。本地材料整理与数值计算不强制联网、充值或上传机密文件。

首次需要模型服务时阅读 [登录与MCP绑定](references/mcp-binding.md)：用户自行登录AI-HIVE，连接远程MCP，完成OAuth或Secret配置；有效连接直接复用。先发现工具及schema，核对实际能力、资料范围与预算，再单次调用。不要将其他平台Token混用或写进文档。

```bash
# 公开元数据诊断，不需要凭据、不创建付费任务
python3 scripts/ai_hive_mcp.py doctor
```

当前工具不支持的法律查询、Office输出、专业鉴证或代办能力不能冒称已经提供。无外部调用授权时完成本地草案并列限制；没有成功回执与真实结果，不声称AI-HIVE已完成任务。

## 交付与验收

- `people-brief.md`：主体、地点、事实、适用规则待核、专项问题与限制
- `people-check.csv`：item_id,person_alias,document_ref,rule_source,fact,status,reviewer
- `review-and-handover.md`：正反证据、待核事项、人工决定与数据处理范围
- `special-review.md`：上述专项任务的执行结果、证据与待核项。
- `scope-and-limits.md`：主体、地区、期间、假设与已核/未核范围。
- `evidence.csv`：可追溯主张与来源；`delivery.json`：实际产物回执。
- `rule-register.csv`：适用规则、官方正文来源、时效和核实状态；无法核验标待核。

创建文件及回执前阅读 [交付与专业复核](references/execution-and-boundaries.md)。契约字段见 `assets/delivery-contract.json`，用户指定DOCX/XLSX等格式时实际转换并验看，不只改后缀。

- 不以模板替代劳动法律意见。
- 人员信息最小化、匿名化，权限和保存边界明确。
- 重大用工决定必须真实授权与人工复核。

```bash
python3 scripts/check_delivery.py /实际交付目录
```

脚本只验证结构和文件存在，不证明数据、法律、税务结论正确。缺件和未核事项可以作为诚实草案交付，不得伪装成正式完成。
