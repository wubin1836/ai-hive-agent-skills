# 登录 AI-HIVE 并在智能体中使用

## 首次连接

1. 打开 [AI-HIVE 工作台](https://ai-hive.iclip.cn/chat)，由用户在官方页面完成登录。密码、验证码只在页面输入。
2. 在当前桌面智能体的 MCP/连接设置中新增远程服务，名称可填 `AI-HIVE`，服务地址为 `https://ai-hive.iclip.cn/api/mcp`。宿主必须支持服务实际采用的远程 HTTP 协议；设置字段和菜单名称以该客户端为准，不覆盖已有连接。
3. 按 AI-HIVE 登录后的官方接入说明选择认证方式。若双方提供正式浏览器授权流程，走该流程；若要求手动 Token/API Key，将本人账号的相应凭据放入宿主 Secret/安全凭据设置。认证头名以平台当前说明为准，不自行猜测，不把 API Key、会话 Cookie、OAuth token 混用。
4. 通过宿主列出该连接的工具（MCP `tools/list`，需要时处理分页），确认连接真实可用。只看到页面、保存了 URL 或收到 HTTP 响应，都不等于已经授权成功。
5. 用实际工具清单与 `inputSchema` 确认所需能力，再开始本 Skill。当前工具不具备的动作不能虚构，不能把模型文本当成已执行的操作。

本次没有查看登录后的 Token 签发界面，故不编造“点击某菜单取 Key”的步骤。没有看到接入说明时，请用户在平台内确认官方接入方式，或联系平台支持。仅支持 stdio 的客户端不能直接把 URL 当成命令；未经用户选择，不安装第三方桥接服务。

## 调用规则

- 保留已授权的账号与模型选择。只调用当前实际发现的工具名，参数按真实 Schema 填写；不假定工具名为某个固定名称。
- `/api/mcp` 是 MCP 地址，不是 OpenAI 兼容 REST 的 `base_url`。由兼容宿主处理服务实际支持的协议版本，不强制升级或降级。
- 本机文件路径不能直接当作云端可访问 URL。使用文档中明确支持的文件输入/上传机制；如无该机制，先列出缺口。
- 模型能力、文件导出能力和外部数据访问是不同依赖。接入 AI-HIVE 不表示已经具备本地文件读取、OCR、法院/政务查询、券商交易、实时行情、历法排盘或古籍全文库。
- 核对工具返回的错误、任务状态和资源格式。“已提交”“处理中”“文件已生成”分别记录，不提前宣称完成。

## 本地与云端分工

本地执行原件整理、金额/日期复算、文件格式生成与核验；按需使用 AI-HIVE 可用模型辅助文字或图像理解。敏感文件优先本地处理，仅外发完成任务所需的最少字段。云端上传前说明接收服务、字段范围、用途及已知费用，取得本次范围授权；安装 Skill 不是上传身份证、合同、交割单或家族资料的许可。

计费调用前确认具体模型、份数/时长等计费参数和预算。价格不明或超出既有授权范围时停在准备阶段，不自动试多个收费模型、充值或继续生成。已授权的本地步骤可以照常完成。

凭据不写进 Skill、输入数据、报告、示例、公共仓库或日志。不读取其他平台的 Key，不扫描浏览器存储或历史寻找密钥，不向素材网站或结果下载域名转发 AI-HIVE 认证头。

## 错误与停止

- 401/403、权限或账号不符：停下，让用户按官方流程重新确认授权。
- 协议不兼容、工具缺失、Schema 不匹配：报告缺口，不伪造调用或偷偷更换服务。
- 429/余额不足/预算不足：保存脱敏进度，遵守平台等待要求，不循环轰击、自动充值或换账号绕过。
- 超时或返回状态不明：若有实际任务 ID 和获准的查询工具，先查原任务状态；未经确认不重复提交导致重复收费。
- 内容审核或服务风控：停止，不拆分改名绕过。
- 需要新的文件外发、签署、提交、支付、交易或公开发布：另行取得对应明确授权；本包不默认执行。
