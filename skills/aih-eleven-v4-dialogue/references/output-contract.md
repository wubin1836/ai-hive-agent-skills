# 多角色音轨与发音验收：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| line_id | 对应实际的 line_id 记录；未知写unknown，不编造。 |
| speaker | 对应实际的 speaker 记录；未知写unknown，不编造。 |
| language | 对应实际的 language 记录；未知写unknown，不编造。 |
| pronunciation | 对应实际的 pronunciation 记录；未知写unknown，不编造。 |
| delivery | 对应实际的 delivery 记录；未知写unknown，不编造。 |
| variant | 对应实际的 variant 记录；未知写unknown，不编造。 |
| output | 对应实际的 output 记录；未知写unknown，不编造。 |
| review | 对应实际的 review 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 每句分配角色情绪，锁定专名发音及顺序
- 根据离线或实时需求选v4或Turbo，先核AI-HIVE可用性
- 分段生成获准小样，保留上下文任务ID保证接句平滑
- 试听重音停顿和跨语言身份，交付逐句音轨与修订单

## 验收门槛

- 厂商推理延迟不等于端到端延迟
- 不克隆无授权真人声音
- 旧版音轨不标为v4测试

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：播客切换语言后，人物不能互换音色。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
