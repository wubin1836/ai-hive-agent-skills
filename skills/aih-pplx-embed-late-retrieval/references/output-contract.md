# 视觉页面检索与多向量适配说明：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| query_id | 对应实际的 query_id 记录；未知写unknown，不编造。 |
| relevant_ids | 对应实际的 relevant_ids 记录；未知写unknown，不编造。 |
| retrieved_ids | 对应实际的 retrieved_ids 记录；未知写unknown，不编造。 |
| modality | 对应实际的 modality 记录；未知写unknown，不编造。 |
| evidence | 对应实际的 evidence 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 保留文档页ID与页码，按文本和图片分批编码，不能塞入单一混合批次
- 核对多向量索引与MaxSim支持；单向量数据库不自动兼容
- 测试9B建索引与0.6B查询路线并记录模型版本，禁止随意跨其它向量空间
- 对表格、页脚和布局歧义做TopK与人工证据验证，输出索引成本及失败页

## 验收门槛

- 不把多向量平均成一个向量冒充原算法
- 检索命中与回答正确分开验收
- PDF敏感页不得默认上传

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：问某合同的价格表，需要找对附件页；仅命中封面不算成功。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
