# 按需工具绑定与热重载验收：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| skill_id | 对应实际的 skill_id 记录；未知写unknown，不编造。 |
| tool_name | 对应实际的 tool_name 记录；未知写unknown，不编造。 |
| activation_state | 对应实际的 activation_state 记录；未知写unknown，不编造。 |
| permission | 对应实际的 permission 记录；未知写unknown，不编造。 |
| expected | 对应实际的 expected 记录；未知写unknown，不编造。 |
| observed | 对应实际的 observed 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 区分发现元数据、激活指令与工具权限，按实际运行时版本确认字段
- 建立技能到工具的最小绑定，在不支持动态加工具的模型上选择明确回退
- 测试未激活工具不可用、已激活权限仍受限以及重载后变更可见
- 交付测试补丁与缓存变化记录，不往所有宿主通用YAML塞专有字段

## 验收门槛

- 加载技能不是授权工具写入
- 不支持的宿主不能保证热重载
- 缓存成本以真实日志判断

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：热重载删掉退款技能后，原会话不得仍能不经确认调用退款工具。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
