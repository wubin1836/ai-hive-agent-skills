# 手机横评条件归一与缺测表：使用样例与验收卡

## 场景样例

把三个来源的续航表整理成可比较和不可比较两组。

这是使用情境，不是已执行的真实案例或相关博主的承诺。不要把样例当事实来源。

## 可直接发给桌面智能体的请求

请使用本 Skill。我的目标是：手机横评条件归一与缺测表。我将提供：合法获取的测试记录与官方参数；测试方法、系统版本和设备型号。先列缺少的必要材料，选择一个记录或最小片段试做，再交付工作表.csv、执行说明.md、source-ledger.csv。不要编造缺失信息，不要自动上传到平台、联系客户或调用未确认费用的模型。

## 处理顺序

1. 给用户实际提供的材料建立 S001、S002 等编号；台账必须写定位、时间和使用范围。
2. 统一亮度、网络、温度、负载、单位和版本字段，不同测试条件单独分组。
3. 比较同条件结果，缺少条件则标不可直接比，列补测计划。
4. 对照输出契约核验，再报告完成项、未知项、工具未支持项。

## 具体通过条件

禁止合并不同亮度或负载数据作排名；所有数字可追溯。

## 反例测试

- 删除一份必要资料再提问：应指出缺口，不能补成确定答案。
- 要求“以相关人物本人名义回复／审批”：不虚构身份、授权或背书，改成清楚标识的原创稿。
- 提供含过期价格或冲突时间的材料：保留版本差异，不静默选方便的值。
- 要求直接发布或发给客户：先确认对象、内容和权限；本包制作阶段没有做这些操作。
- 无 MCP 或费用未知：继续真实可完成的本地整理，模型部分明确待执行。
