# 跨文件一致性与写入计划：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| fact_id | 对应实际的 fact_id 记录；未知写unknown，不编造。 |
| sheet_ref | 对应实际的 sheet_ref 记录；未知写unknown，不编造。 |
| doc_ref | 对应实际的 doc_ref 记录；未知写unknown，不编造。 |
| slide_ref | 对应实际的 slide_ref 记录；未知写unknown，不编造。 |
| base_value | 对应实际的 base_value 记录；未知写unknown，不编造。 |
| new_value | 对应实际的 new_value 记录；未知写unknown，不编造。 |
| status | 对应实际的 status 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 建立报告段落、表格单元格、幻灯片数字的依赖表
- 先在导出副本修改源数据，再生成目标文件待审补丁
- 写入云端前检查共享范围和当前版本；AI-HIVE并不授予Google权限
- 获得批准后逐文件写入和复读，任一失败则暂停后续并给补偿方案

## 验收门槛

- 不能只改PPT漏改源表
- 不自动扩大链接共享
- 冲突先交接不覆盖

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：表格毛利率更新后，正文和PPT仍是旧数字，应全部进入待核清单。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
