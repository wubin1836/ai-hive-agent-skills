# 多关键帧约束与连续性检查：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| frame_id | 对应实际的 frame_id 记录；未知写unknown，不编造。 |
| time_s | 对应实际的 time_s 记录；未知写unknown，不编造。 |
| subject_state | 对应实际的 subject_state 记录；未知写unknown，不编造。 |
| camera | 对应实际的 camera 记录；未知写unknown，不编造。 |
| transition | 对应实际的 transition 记录；未知写unknown，不编造。 |
| source_path | 对应实际的 source_path 记录；未知写unknown，不编造。 |
| review | 对应实际的 review 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 给关键帧设置递增时间和过渡意图，冲突的场景状态先协调
- 确认工具支持的关键帧数量和时长，不强套厂商规格到中转接口
- 做短段测试，检查经过中间帧时动作连续而不是静帧拼贴
- 交付关键帧时间表、实际片段与未满足约束，无法调用时提供中性任务包

## 验收门槛

- 不得保证每帧像素级锁定
- 素材权利需确认
- 时间点应在总片长内

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：角色坐下到起身必须给动作过渡，不能用两张冲突姿势要求瞬间连续。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
