# 游泳教练助手：任务示例

## 场景一：用最小材料核对结果

用户请求：整理本次游泳课出勤和观察

演示资料（全部虚构，不含真实个人资料）：

> 虚构测试材料，无个人信息：A组三人N1至N3、B组两人N4至N5；实际N1至N4到课，N5缺席；教练仅记录N1、N2达到本课观察点，其余未评。

应得到的结果：报名5、到课4、缺席1；仅N1、N2写已观察达标，N3、N4未评，N5不评；不生成无人监督练习指令。

处理时按SKILL.md的职业流程回查每个原始事实。不能把这里的演示结论套到别人的真实资料上。

模型接入参考（本例仅凭所给文本即可核对，不需要付费模型）：

```bash
# 可选的独立公开接入诊断，不会代替上面的职业分析
python3 scripts/ai_hive_mcp.py doctor
```

## 场景二：把用户真实资料变成岗位成果

可直接使用的任务说明：

```text
请作为游泳教练助手，处理我本次提供的资料。
需要的资料类型：教练确认课程目标、场馆规则、脱敏学员分组与人工观察记录。
期望成果：交付分组课前核对表、技能观察记录和家长反馈草稿。
先核对来源、适用规则和缺项；不要把待确认写成已完成。
如果我需要实际文件，请用可用工具制作并检查，保留原件。
我没有授权上传、付费、外发或业务系统改动，不要自动执行这些动作。
```

根据用户给出的实际资料开展工作，不要求用户为套模板重复输入已知信息。本场景没有预设业务数值，正确结果必须来自本次材料；先给必要缺项，再交付已完成部分。

只有需要AI-HIVE模型并且本脚本进程已获得安全凭据时，先列工具：

```bash
python3 scripts/ai_hive_mcp.py list-tools
# 仅当当前工具列表存在时使用以下历史查询名
python3 scripts/ai_hive_mcp.py describe ai_hive_list_models
```

模型参数JSON须按当前schema与本次输入创建，不发送占位符。仅当用户明确要求额外图片并确认付费、素材和数量后，才可能使用下面路径：

```bash
# 以下历史工具名也必须先在当前列表中验证
python3 scripts/ai_hive_mcp.py describe ai_hive_generate_image
# approved-request.json由本次真实schema和获准素材构成；不是随包空模板
python3 scripts/ai_hive_mcp.py call ai_hive_generate_image --args-file approved-request.json --confirm-paid
```

视频或其他调用同样先发现实际工具；未发现就不要猜名字。`--confirm-paid`只在已有明确授权时使用。拿到任务ID后继续查询同一任务，不能将待处理响应描述成成品。

## 验收提示

- 先核对演示中的已知事实与结果，再处理真实输入。
- 不替代现场教练救生员，不给无人监督训练或救援指令；未成年人资料需监护授权。
- 文件能打开、数字能复算、出处能回查才算相应环节完成；空模板、计划和提示词不能冒充业务结果。
