# 专项执行参考

仅供材料准备与核对参考；具体要求以办理地当前官方规则为准，不保证资格或审批结果。

## 资料与交付约定

先确认任务地区/版本/时间范围及输出目录。证据表至少有 source_id、原文件页码或行号、原文、处理值、状态；状态使用 confirmed / uncertain / missing。来源身份与用户隐私不要在公开示例中泄露。

## 本项处理检查

- 已办、待办及待确认状态分别记录，避免建议重复注销或重复申请
- 行政证件、待遇办理与遗产处分分开，不自行认定继承人
- 证明材料按用途最小化引用，每个前置关系有地方指南依据

## 示例请求（虚构输入，仅说明调用方式）

仅示例，以下文件名和情境均为假设，不表示已存在真实数据：假设我已提供 示例_家属指定地区及已办事项.json、示例_当地身后一件事指南.pdf、示例_必要证明目录.csv。请使用「亲人去世后办事清单助手」，为家属整理尚未办理的行政事项和所需证明，按前置依赖排序，涉及遗产的事项另标专业咨询。将结果写入我指定的本地目录，交付 after-death-official-checklist-checklist.xlsx、after-death-official-checklist-evidence.docx、after-death-official-checklist-sources.json。本例先离线处理；输入、工具或适用规则不足时先交缺口说明，不编造结果。需要联网更新来源先征得我同意，不登录账户、不代提交或付款。

## 交付验收

- 按实际产物检查文件结构，不能将 Markdown 改后缀冒充 DOCX/XLSX/PDF。
- 公式、金额、日期和图式编码使用脚本或可审查公式复算；模型生成的数字未经复算不能标为已核验。
- DOCX/PDF应渲染检查页码、字体与批注；XLSX回读表头、数据类型和公式；SVG/HTML实际预览。工具缺失则说明哪项视觉/内容验收未完成。
- 缺少输入时交缺件列表，不创建虚构的全套结果来通过核验；仅完成部分时清楚列出已交与未交。

## 专业与使用边界

仅整理用户授权资料并核对当前属地官方来源，不作资格、批准或专业安全保证，不代登录、签名、提交、支付。实际运行时须重新核验政策及来源；个人隐私最小化。
