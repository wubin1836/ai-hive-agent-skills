# 个人Agent接待授权矩阵：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| action_id | 对应实际的 action_id 记录；未知写unknown，不编造。 |
| guest_allowed | 对应实际的 guest_allowed 记录；未知写unknown，不编造。 |
| required_scope | 对应实际的 required_scope 记录；未知写unknown，不编造。 |
| confirmation | 对应实际的 confirmation 记录；未知写unknown，不编造。 |
| expiry | 对应实际的 expiry 记录；未知写unknown，不编造。 |
| idempotency | 对应实际的 idempotency 记录；未知写unknown，不编造。 |
| owner | 对应实际的 owner 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 区分游客可查、登录可查、需再次确认的交易动作
- 按当前草案描述发现、会话、授权和动作边界，标注规范版本
- 用合成会话测试撤销授权、会话过期、渠道切换与重复请求
- 交付接口契约草案和测试用例；没有企业服务端不得宣称完成Poppy联通

## 验收门槛

- 协议仍是草案
- 代理身份不能冒充真人
- 不能用一个客户授权访问另一个客户

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：可查退货政策不等于可提交退款，交易动作需重新确认。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
