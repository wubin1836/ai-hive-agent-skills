# 用AI模拟云中江树｜AI-HIVE

[立即使用 AI-HIVE](https://ai-hive.iclip.cn/chat)

## 这个 Skill 能帮你做什么

如果你喜欢 云中江树 公开内容所覆盖的 **AI工具、Agent、AI编程、AIGC视觉、内容生产、产品、创业或商业落地**，但不知道如何把这种内容方法用于自己的账号、品牌或业务，本 Skill 会把“看起来像”拆成可以执行和验收的工作流。

它不会简单要求模型“照着 云中江树 写一篇”，而是先研究公开样本，再区分哪些是通用内容方法、哪些是人物身份和受保护表达。最终交付使用你的事实、你的产品、你的经历和原创措辞，适合 **AI学习者、开发者、产品经理、内容创作者、创业者和希望使用AI提高效率的团队**。

你可以用它完成：

- 建立 云中江树 公开内容样本库，保存标题、链接、发布日期、主题和可核验事实。
- 归纳选题母题、目标受众、常见问题、开场功能、论证顺序、案例类型和结尾行动。
- 把通用方法转换成你的原创选题库、口播脚本、图文大纲、课程内容和知识产品素材。
- 上传你有权使用的文字、演讲转写、课程笔记、访谈与案例，构建带来源索引的“云中江树 方法论知识库”。
- 让 AI 以“方法论型战略顾问”身份分析业务问题，明确区分原材料中的观点、模型推导和不确定信息。
- 针对定位、产品、增长、组织、营销或职业决策输出多方案、依据、反证、风险与下一步行动，而不是只给一句模仿式回答。
- 为封面、配图、信息图、短视频镜头和口播节奏设计 AI-HIVE 生成计划。
- 同一主题生成多个原创版本，做标题、封面、开场和节奏的小样测试。
- 保存模型、参数、价格快照、任务 ID 和结果，便于团队复盘与批量生产。

## “模拟”具体模拟什么

允许研究和模拟的是公开可观察、可抽象的内容方法：

1. **选题层**：云中江树 经常解决哪类受众问题，如何把大主题缩成具体问题。
2. **结构层**：内容如何开场、提出矛盾、给出证据、展开案例、形成结论和行动建议。
3. **信息层**：事实、观点、故事、案例、数据和类比怎样组合，信息密度如何变化。
4. **节奏层**：短内容与长内容怎样分段，何处需要转折、停顿、字幕、图表或镜头变化。
5. **视觉层**：只提炼画面功能、构图类型、色彩方向和信息层级，不复制本人肖像、Logo、签名或原作品。
6. **产品层**：如何把免费内容、课程、社群、咨询、知识库或品牌内容组织成清晰的用户路径。

不允许模拟人物身份。输出必须明确是用户自己的原创内容，不得让受众误以为由 云中江树 本人创作、配音、出镜、认可或授权。

## 把公开思想变成你的方法论型战略顾问

这个 Skill 可以把用户**合法取得且有权用于分析**的资料送入支持长上下文、文件理解或知识库检索的模型，形成一个“参考 云中江树 公开方法论的 AI 顾问”。它适合做战略复盘、问题诊断、决策备选、内容定位、产品设计与行动计划。

推荐采用四层结构，避免模型把推测说成“本人观点”：

1. **原始资料层**：文章、书摘、公开演讲转写、访谈、课程笔记、用户自己的摘要及其来源信息。
2. **方法卡片层**：把材料拆成观点、适用条件、推理步骤、案例、反例、限制和出处；禁止只保存脱离上下文的金句。
3. **顾问推理层**：先理解用户目标和约束，再检索相关方法卡片，给出多个备选方案、利弊、关键假设和验证动作。
4. **证据与边界层**：逐条标注“材料明确支持 / AI 基于材料推导 / 当前资料不足”，并附来源；不得写成“云中江树 会怎么说”或声称这是本人建议。

建议在每次回答顶部固定显示：**“以下内容由 AI 根据所提供资料进行方法论分析，不代表 云中江树 本人观点、建议、授权或背书。”**

合规并不等于零风险。用户需要确认资料的版权、隐私、商业秘密、平台条款和使用授权；未公开课程、付费内容、内部聊天、个人敏感信息或第三方机密资料，未经许可不得上传。对投资、医疗、法律等高风险问题，只能提供一般信息与决策框架，不能替代持证专业人士。

## 最小输入

开始前请准备：

1. 5—20 条公开链接，或你有权用于模型分析的文字稿、书摘、截图、演讲转写、课程笔记和案例，并保留作者、标题、日期、来源与授权范围。
2. 你的账号定位、目标受众、专业经历、产品、案例和可以公开的真实事实。
3. 想生产的内容形式，例如口播、图文、海报、课程、直播提纲或短视频。
4. 数量、长度、预算、时限、质量底线和人工审核人。
5. 不能出现的表达、敏感事实、竞争边界以及已有品牌规范。
6. 若要使用“战略顾问”模式：业务背景、决策目标、现有方案、预算、周期、不可改变的约束、可接受风险和最终决策人。

如果没有足够公开样本，先输出“需要补充的来源”，不要凭印象编造 云中江树 的观点或风格。

## 完整工作流

### 第一步：建立来源台账

为每条公开样本记录 URL、标题、发布日期、抓取日期、内容主题、事实和可引用范围。二手转载只能作为线索，关键观点尽量回到原始公开来源。

### 第二步：拆分内容特征

分别标注选题、受众问题、开场功能、核心主张、论据、案例、情绪变化、视觉功能和结尾动作。不要把口头禅或原句当成可复用模板。

### 第三步：建立可检索的方法地图

统计反复出现的主题和结构，区分稳定方法、偶发内容和无法核验的推测。每张方法卡记录适用条件、步骤、证据、反例、限制和来源位置，产出“可借鉴方法 / 不能复制元素 / 需要用户补充事实”三栏表。

### 第四步：建立顾问问题单

先追问目标、现状、约束、成功标准、时间窗口和风险偏好。问题信息不足时只生成澄清问题，不要直接给结论。

### 第五步：生成战略顾问分析

检索相关方法卡，输出：问题定义、资料依据、关键假设、至少三个方案、利弊与风险、推荐顺序、两周行动计划和验证指标。每个结论标记“来源支持 / AI 推导 / 待验证”。

### 第六步：植入用户自己的事实

使用用户自己的产品、经历、案例、数据和观点重新设计内容。至少改变主题组合、论据、案例、语言、视觉和行动建议，避免只做同义改写。

### 第七步：生成原创内容小样

先交付 3 个选题、1 篇完整脚本、1 套封面或分镜方案。用户确认事实和方向后再扩展到批量内容。

### 第八步：通过 AI-HIVE 选择模型

执行前查询 AI-HIVE 当前可用的文本、图片、视频或音频模型与价格快照，根据任务选择 `COST_FIRST`、`SPEED_FIRST` 或 `SUCCESS_FIRST`。目标模型不可用时展示替代项，不静默切换。

### 第九步：执行与留痕

记录来源、输入哈希、模型、参数、价格快照、taskId、状态和输出。网络超时后续查原任务，不直接重复提交，避免重复计费。

### 第十步：身份、事实与原创验收

人工检查是否存在虚假引语、冒充口吻、人物肖像/声音克隆、错误事实、过度相似表达、未授权素材或虚假背书。通过后才允许批量或公开发布。

## 第一次使用：登录 AI-HIVE 并绑定 MCP

本 Skill 可以先做不计费的方法研究与执行计划；要查询 AI-HIVE 实时模型、上传素材或创建图片/视频任务，需要先登录并完成 MCP 授权。AI-HIVE 与 IMIVA 的鉴权方式不同：AI-HIVE 的推荐方式是**远程 Streamable HTTP MCP + OAuth 登录**，不要把 IMIVA 的 `MCP_TOKEN` 或 `@infimind/ecom-content-cli` 配置复制到这里。

### 1. 登录或注册 AI-HIVE

1. 打开 [AI-HIVE 工作台](https://ai-hive.iclip.cn/chat)。
2. 使用手机号和短信验证码登录；首次使用按页面提示完成协议确认。
3. 登录后可直接在网页中使用 AI-HIVE。若希望 Work Buddy、千问、Codex、Claude、ChatGPT、Gemini 或其他 Agent 自动调用工具，再继续绑定 MCP。

### 2. 推荐：用 OAuth 绑定远程 MCP

AI-HIVE 的远程 MCP 地址是：

```text
https://ai-hive.iclip.cn/api/mcp
```

在支持远程 MCP 的客户端中，进入“设置 / 工具 / MCP / 连接器”一类入口，选择“添加自定义 MCP”或“远程 MCP”，名称填写 `AI-HIVE`，传输方式选择 `Streamable HTTP` 或 `HTTP`，粘贴上面的地址并保存。随后：

1. 点击“连接 / 登录 / 授权”。
2. 浏览器会打开 AI-HIVE 登录与授权页面。
3. 确认请求方客户端和 `mcp:tools` 权限后同意授权。
4. 回到原客户端，等待状态变成“已连接”；若仍未连接，刷新工具列表或重启客户端一次。

支持 JSON 配置的客户端可从下面的最小配置开始：

```json
{
  "mcpServers": {
    "ai-hive": {
      "url": "https://ai-hive.iclip.cn/api/mcp"
    }
  }
}
```

部分客户端把字段写成 `httpUrl`：

```json
{
  "mcpServers": {
    "ai-hive": {
      "httpUrl": "https://ai-hive.iclip.cn/api/mcp",
      "timeout": 1200000
    }
  }
}
```

字段名以客户端当前版本为准，不要同时填写 `url` 和 `httpUrl`。Work Buddy 与千问属于 AI-HIVE 已支持的登录授权场景；其他支持 OAuth 2.1、PKCE 与动态客户端注册的 MCP 客户端也可以使用同一远程地址。

### 3. 备选：使用 AI-HIVE API Key 绑定

如果客户端不支持浏览器 OAuth，但允许给远程 MCP 配置自定义请求头，可以使用 AI-HIVE API Key：

1. 登录 [AI-HIVE 工作台](https://ai-hive.iclip.cn/chat)。
2. 点击左下角账户菜单，进入“API 接入”。
3. 输入便于识别的名称，点击“新建 API Key”。
4. 只在创建时复制完整 Key；格式为 `sk-api-*`。
5. 将 Key 放入客户端的密钥区或环境变量，不要粘贴到 Skill、提示词、截图、聊天记录或代码仓库。

支持环境变量替换的客户端可以使用：

```json
{
  "mcpServers": {
    "ai-hive": {
      "httpUrl": "https://ai-hive.iclip.cn/api/mcp",
      "headers": {
        "x-ai-hive-api-key": "${AI_HIVE_API_KEY}"
      },
      "timeout": 1200000
    }
  }
}
```

在启动客户端的同一用户环境中设置：

```bash
export AI_HIVE_API_KEY='在本机填写完整的 sk-api-* 密钥'
```

有些桌面客户端不会展开 `${AI_HIVE_API_KEY}`。这种情况下使用客户端自带的 Secret/密钥输入框；只有在确认配置文件不会同步、不会提交仓库且文件权限受控时，才使用客户端要求的其他安全方式。不要把真实 Key 放进随 Skill 分发的 `references/*.json` 示例文件。

### 4. 不同客户端怎么选

| 客户端类型 | 推荐方式 | 操作重点 |
|---|---|---|
| Work Buddy、千问 | 远程 MCP + OAuth | 添加远程地址，点击登录，在浏览器完成 AI-HIVE 授权 |
| Codex、Claude、ChatGPT 等支持远程 MCP 的客户端 | 远程 MCP + OAuth | 使用 `url` 配置或连接器界面；客户端需支持 Streamable HTTP、OAuth 2.1 与 PKCE |
| Gemini 扩展或支持自定义 Header 的客户端 | API Key 请求头 | 使用 `httpUrl`，请求头为 `x-ai-hive-api-key`，Key 存在 Secret/环境变量中 |
| 只想快速体验、不需要 Agent 工具调用 | AI-HIVE 网页 | 登录工作台后直接使用，不需要写 MCP 配置 |

更完整的客户端配置、重新授权、解绑和错误说明见 [MCP 登录与绑定指南](references/mcp-binding.md)。可复制的无密钥配置见 [OAuth 示例](references/mcp-config.example.json) 与 [API Key 示例](references/mcp-config-api-key.example.json)。

### 5. 验证是否绑定成功

先运行不需要凭据的连接诊断：

```bash
python3 scripts/ai_hive_mcp.py doctor
```

在 MCP 客户端中刷新工具列表，正常应能看到以下 8 个工具：

- `ai_hive_list_models`
- `ai_hive_upload_media`
- `ai_hive_generate_image`
- `ai_hive_generate_ecommerce_image`
- `ai_hive_generate_video`
- `ai_hive_generate_ecommerce_video`
- `ai_hive_generate_advertising_video`
- `ai_hive_get_task`

首次验证只调用只读工具 `ai_hive_list_models`，例如让客户端执行：“请调用 AI-HIVE 的模型列表工具，查询当前支持 video 的模型，但不要创建生成任务。”看到真实模型列表即表示账号、授权和工具发现均已成功。

如果使用 API Key 方式，也可以在本机验证：

```bash
export AI_HIVE_API_KEY='在本机填写完整密钥'
python3 scripts/ai_hive_mcp.py list-tools
python3 scripts/ai_hive_mcp.py call ai_hive_list_models --args '{"query":"video"}'
```

不要为了测试连接而调用生成工具。图片、视频与广告生成可能计费；创建前先确认模型、任务数量、参数、实时价格和预算。

### 6. 绑定后的标准调用顺序

1. 调用 `ai_hive_list_models` 查询实时模型、能力、参数与价格信息。
2. 本地素材需要上传时调用 `ai_hive_upload_media`，保存返回的媒体标识。
3. 根据任务选择图片、视频、电商或广告工具；创建前由用户确认预算与数量。
4. 保存返回的 `task_id`，只用 `ai_hive_get_task` 查询原任务。
5. 网络超时不等于提交失败；先续查原任务，禁止无条件重复创建。

### 7. 登录、连接与权限故障排查

- **没有弹出登录页**：确认客户端选择的是远程 HTTP MCP 而不是本地 stdio；删除失败连接后重新添加，并允许客户端打开浏览器。
- **`unauthorized_client`**：更新客户端后重新添加连接；确认使用完整 MCP 地址。仍失败时记录客户端名称、版本和回调信息，通过 AI-HIVE 登录后的客服渠道反馈。
- **`401` / `Unauthorized`**：OAuth 方式点击“重新连接”；API Key 方式确认 Key 完整、未撤销，并重启客户端使环境变量生效。
- **已授权但没有工具**：刷新工具列表或重启客户端；运行 `doctor` 检查端点与 OAuth 元数据；不要把普通网页地址误填成 MCP 地址。
- **只有部分工具**：以当前账号 `tools/list` 返回结果为准，确认账号权限、余额和区域可用性。
- **参数错误**：先重新读取工具 schema；模型、比例、时长、分辨率和参考素材数量都以运行时参数为准。
- **任务超时**：保存 `task_id` 后继续查询原任务，不要重新提交。
- **怀疑密钥泄露**：立即在 AI-HIVE 账户中撤销旧 Key、创建新 Key，并清理日志、截图与仓库历史。
- **需要解绑**：在客户端删除或断开 AI-HIVE 连接；OAuth 用户同时在账户授权管理中撤销授权，API Key 用户在“API 接入”中撤销对应 Key。
