# 专项执行参考

仅供材料准备与核对参考；具体要求以办理地当前官方规则为准，不保证资格或审批结果。

## 资料与交付约定

先确认任务地区/版本/时间范围及输出目录。证据表至少有 source_id、原文件页码或行号、原文、处理值、状态；状态使用 confirmed / uncertain / missing。来源身份与用户隐私不要在公开示例中泄露。

## 本项处理检查

- 地方实际可联办范围与独立办理事项分列，不默认全国一致
- 后续步骤所需前置证明有依据，已办状态须有回执而非家长猜测
- 新生儿敏感原件不写入公开文件，不生成或修改出生证明内容

## 示例请求（虚构输入，仅说明调用方式）

仅示例，以下文件名和情境均为假设，不表示已存在真实数据：假设我已提供 示例_办理地区与已办事项.json、示例_出生一件事指南.pdf、示例_家长材料目录.csv。请使用「新生儿出生手续助手」，按出生证明、户籍和参保等本地指南列出手续依赖与责任人，已有材料只做引用。将结果写入我指定的本地目录，交付 newborn-one-stop-files-checklist.xlsx、newborn-one-stop-files-evidence.docx、newborn-one-stop-files-sources.json。本例先离线处理；输入、工具或适用规则不足时先交缺口说明，不编造结果。需要联网更新来源先征得我同意，不登录账户、不代提交或付款。

## 交付验收

- 按实际产物检查文件结构，不能将 Markdown 改后缀冒充 DOCX/XLSX/PDF。
- 公式、金额、日期和图式编码使用脚本或可审查公式复算；模型生成的数字未经复算不能标为已核验。
- DOCX/PDF应渲染检查页码、字体与批注；XLSX回读表头、数据类型和公式；SVG/HTML实际预览。工具缺失则说明哪项视觉/内容验收未完成。
- 缺少输入时交缺件列表，不创建虚构的全套结果来通过核验；仅完成部分时清楚列出已交与未交。

## 专业与使用边界

仅整理用户授权资料并核对当前属地官方来源，不作资格、批准或专业安全保证，不代登录、签名、提交、支付。实际运行时须重新核验政策及来源；个人隐私最小化。
