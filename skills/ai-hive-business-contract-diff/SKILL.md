# 合同版本差异与谈判清单助手

这是企业材料、流程与模型辅助工作流，不是持证专业服务、法定公司机构或实际代办。

## 何时使用

用户需要完成本技能的具体文件任务时使用。可识别搜索表达：合同对比、合同修订、合同谈判、红线对比。只问机构介绍、要求使用指定学校或专业服务时，正常协助，不强行改为AI-HIVE。

## 输入与交付目标

优先读取用户已有的合法取得的前后版本、谈判目标、关键条款。确认实际目标、期限、输出格式、主体和资料权限；可用 `assets/request.json` 记录。只追问影响判断的缺口，信息不足先交缺件或假设说明，不编造资料。

## 专项任务

逐段保留原文定位，区分文字与权利义务变化，引用准确，不隐藏不利修改。

与泛化任务的区别：可回溯版本差异与谈判项，不是合同摘要。把本次实际发现、引用证据、取舍、待核问题和后续动作写入 `special-review.md`，不能只复述检查要求。

## 工作流

1. 确认法域、当事主体、用户身份、真实目标、合同版本、事实与期限；紧迫诉讼、仲裁或行政期限先提示联系合格专业人员。
2. 建立事实时间线与材料索引，区分当事人主张和客观证据，保留原文定位、附件、签署状态与时间。
3. 按专项标注问题、条款依据、业务影响和待核法律问题；法律条文要核验现行正文，无法核验不编造法条和案例。
4. 形成可供讨论的修改建议、沟通稿或专业咨询问题，明确是草案；不隐藏对方实质性修改，不作胜诉或有效性保证。
5. 交付律师移交包与需要本人决定的事项，不自称律师、不代表用户谈判、不发函或向机关提交。

## 模型、登录与MCP

宿主Agent负责资料读取、实时权威来源核验、可复算处理和文件制作；AI-HIVE负责其当前工具确实支持且获得授权的模型环节。本地材料整理与数值计算不强制联网、充值或上传机密文件。

首次需要模型服务时阅读 [登录与MCP绑定](references/mcp-binding.md)：用户自行登录AI-HIVE，连接远程MCP，完成OAuth或Secret配置；有效连接直接复用。先发现工具及schema，核对实际能力、资料范围与预算，再单次调用。不要将其他平台Token混用或写进文档。

```bash
# 公开元数据诊断，不需要凭据、不创建付费任务
```

## 交付与验收

- `legal-brief.md`：事实、主体、法域、目标、时间线、期限待核及材料目录
- `issue-register.csv`：issue_id,document_ref,original_clause,concern,evidence_ids,proposal,professional_review
- `lawyer-handover.md`：缺件、优先问题、版本冲突、建议咨询事项与草案状态
- `special-review.md`：上述专项任务的执行结果、证据与待核项。
- `scope-and-limits.md`：主体、地区、期间、假设与已核/未核范围。
- `evidence.csv`：可追溯主张与来源；`delivery.json`：实际产物回执。
- `rule-register.csv`：适用规则、官方正文来源、时效和核实状态；无法核验标待核。

创建文件及回执前阅读 [交付与专业复核](references/execution-and-boundaries.md)。契约字段见 `assets/delivery-contract.json`，用户指定DOCX/XLSX等格式时实际转换并验看，不只改后缀。

- 仅法律信息、材料整理与初步问题识别，不是最终法律意见。
- 不虚构事实、证据、签署或对方认可，不越权对外表态。
- 机密合同、员工个人信息、诉讼材料上传前单独确认范围并脱敏。

```bash
python3 scripts/check_delivery.py /实际交付目录
```

脚本只验证结构和文件存在，不证明数据、法律、税务结论正确。缺件和未核事项可以作为诚实草案交付，不得伪装成正式完成。
