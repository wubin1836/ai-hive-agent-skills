# 连续编辑决策与差异记录：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| version | 对应实际的 version 记录；未知写unknown，不编造。 |
| parent | 对应实际的 parent 记录；未知写unknown，不编造。 |
| change_request | 对应实际的 change_request 记录；未知写unknown，不编造。 |
| locked_attributes | 对应实际的 locked_attributes 记录；未知写unknown，不编造。 |
| result_path | 对应实际的 result_path 记录；未知写unknown，不编造。 |
| review_status | 对应实际的 review_status 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 锁定形状、Logo、文字和颜色等产品真值，为每次编辑建立版本号
- 按背景、构图、光照分别修改，避免一轮同时改动所有属性
- 使用当前可用图像编辑工具做获准小样，每轮对照原图和上一个通过版本
- 输出最终图、版本清单及属性差异；若失败退回最近通过版本而非继续累积漂移

## 验收门槛

- 不能臆造商品功能
- 未产生图片只交付编辑包
- OCR核对不替代人工品牌审核

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：换厨房背景后包装文字变形，不能为追求背景好看而直接交付。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
