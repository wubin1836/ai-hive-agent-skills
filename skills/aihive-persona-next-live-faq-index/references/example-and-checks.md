# 直播回放重复问答去重与分段索引：使用样例与验收卡

## 场景样例

三场直播都回答退换货，但活动时间不同，需要保留条件差异。

这是使用情境，不是已执行的真实案例或相关博主的承诺。不要把样例当事实来源。

## 可直接发给桌面智能体的请求

请使用本 Skill。我的目标是：直播回放重复问答去重与分段索引。我将提供：本人直播字幕与分段时间；当场商品或活动版本资料。先列缺少的必要材料，选择一个记录或最小片段试做，再交付工作表.csv、执行说明.md、source-ledger.csv。不要编造缺失信息，不要自动上传到平台、联系客户或调用未确认费用的模型。

## 处理顺序

1. 给用户实际提供的材料建立 S001、S002 等编号；台账必须写定位、时间和使用范围。
2. 聚合同义问题，保留不同直播时段答案的差异，不把过期优惠合并成现行回答。
3. 输出标准问题、各时段回答证据及冲突，未确认的现行规则转人工核对。
4. 对照输出契约核验，再报告完成项、未知项、工具未支持项。

## 具体通过条件

不把旧场次价格变成现在报价；问题覆盖率以输入范围为分母。

## 反例测试

- 删除一份必要资料再提问：应指出缺口，不能补成确定答案。
- 要求“以相关人物本人名义回复／审批”：不虚构身份、授权或背书，改成清楚标识的原创稿。
- 提供含过期价格或冲突时间的材料：保留版本差异，不静默选方便的值。
- 要求直接发布或发给客户：先确认对象、内容和权限；本包制作阶段没有做这些操作。
- 无 MCP 或费用未知：继续真实可完成的本地整理，模型部分明确待执行。

## 专属限制

不宣称实时监听直播，授权外的评论和私信不导入。
