# 专项执行参考

仅供材料整理和初步核对参考，不替代执业律师意见，不保证诉讼结果，不自动提交或签署。

## 资料与交付约定

先确认任务地区/版本/时间范围及输出目录。证据表至少有 source_id、原文件页码或行号、原文、处理值、状态；状态使用 confirmed / uncertain / missing。来源身份与用户隐私不要在公开示例中泄露。

## 本项处理检查

- 只做民事上诉材料。先检查案件类别、审级、送达与程序状态；刑事申诉、行政复议和民事再审不能套用此模板。
- 不得凭模型记忆填写统一期限或受理法院。执行时读取适用的现行官方规定、裁判告知并交用户或律师核验。临近期限应先提示及时寻求专业帮助。
- 逐项建立 appeal_request → judgment_page → disputed_finding → evidence_id → missing_fact 映射；未确认事实保留占位，不编造证据或法条。
- 生成DOCX后检查案号、姓名占位、金额和每个附件引用；渲染检查页码与批注。写明“讨论稿/待专业审核”，不替用户签字、提交或缴费。

## 示例请求（虚构输入，仅说明调用方式）

仅示例（下列文件名和资料均为假设，不是真实数据）：请读取假设文件一审裁判.pdf、送达资料.pdf、原审证据目录.xlsx和不服事项.docx，按我确认的不服部分生成上诉请求—理由—证据表及 civil-appeal-draft.docx，程序不明先列问题。

## 交付验收

- 按实际产物检查文件结构，不能将 Markdown 改后缀冒充 DOCX/XLSX/PDF。
- 公式、金额、日期和图式编码使用脚本或可审查公式复算；模型生成的数字未经复算不能标为已核验。
- DOCX/PDF应渲染检查页码、字体与批注；XLSX回读表头、数据类型和公式；SVG/HTML实际预览。工具缺失则说明哪项视觉/内容验收未完成。
- 缺少输入时交缺件列表，不创建虚构的全套结果来通过核验；仅完成部分时清楚列出已交与未交。

## 专业与使用边界

本条仅民事上诉材料准备；不等同申诉、再审或重新起诉。不得保证改判，不给统一具体期限，不自动提交、撤回上诉或缴费。
