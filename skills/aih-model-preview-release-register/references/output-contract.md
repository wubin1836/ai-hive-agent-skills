# 模型可用性登记册：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| model_id | 对应实际的 model_id 记录；未知写unknown，不编造。 |
| announcement_date | 对应实际的 announcement_date 记录；未知写unknown，不编造。 |
| api_status | 对应实际的 api_status 记录；未知写unknown，不编造。 |
| weights_status | 对应实际的 weights_status 记录；未知写unknown，不编造。 |
| region | 对应实际的 region 记录；未知写unknown，不编造。 |
| aihive_status | 对应实际的 aihive_status 记录；未知写unknown，不编造。 |
| evidence | 对应实际的 evidence 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 为公告日、API开放日、权重开放日与地区权限分别建字段
- 核对别名、预览后缀和废弃日期，矛盾来源保留并标待核
- 将官方可用和AI-HIVE当前可用分开，无登录证据不得推定账号可用
- 输出可试用、需申请、仅预告及未证实清单，附下一次应核验条件

## 验收门槛

- 没有权重下载链接不写已开源
- 平台列名不等于当前账户授权
- 不虚构后续核验已完成

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：公告说月底开放权重，今天只标API预览，不提供编造的本地部署命令。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
