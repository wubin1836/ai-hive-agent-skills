# 按问题选页识别与原文取证助手：场景示例

## 场景一：首次执行

```text
请从这六份设备手册查找工作温度和安装间距。先做页级索引，再识别相关扫描区域，列出每个数字的页码及未核实页面，不把全部文档上传外部。
```

输入记录示例：

```json
{
  "mode": "演示数据",
  "question": "安装间距是多少",
  "pages": [
    {
      "page": 1,
      "text": "目录：安装见8页"
    },
    {
      "page": 8,
      "text": "",
      "scanned": true
    }
  ]
}
```

人工构造的输出片段，仅用于解释格式；不是付费模型生成结果或测试成绩：

```json
{
  "illustrative_only": true,
  "sample": {
    "mode": "人工演示，未调用OCR",
    "target_pages": [
      8
    ],
    "answer": null,
    "next": "用获准OCR或人工查看第8页并记录区域",
    "full_document_verified": false
  }
}
```

## 场景二：复核与返工

```text
请检查本次输出是否满足：页面选择依据与实际识别范围清楚。；答案都附页码和原始证据位置。；文本层空白不直接判定扫描页无信息。；按需识别结果不标为全量建库完成。。
把结论分成已验证、未验证、需补资料三类。只修复有证据的问题，不覆盖原文件；先列返工清单和额外调用费用。
```

复核记录建议字段：`check / evidence / actual / status / next_action`。

## 场景三：当前模型或工具不可用

```text
如果当前AI-HIVE没有本任务需要的精确模型或工具，请不要生成冒名结果。给我已发现的能力、缺失条件、可先完成的本地准备材料，以及需要我选择的替代方案。
```

本地演练：在MCP未配置时仍可执行 `scripts/workflow.py`，但其结果必须保持 `phase=offline_plan`、`model_calls=0`。这只能验证工作单，不是验证模型能力。
