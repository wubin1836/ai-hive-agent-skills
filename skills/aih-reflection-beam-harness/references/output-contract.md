# harness兼容矩阵与回滚单：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| case_id | 对应实际的 case_id 记录；未知写unknown，不编造。 |
| model | 对应实际的 model 记录；未知写unknown，不编造。 |
| status | 对应实际的 status 记录；未知写unknown，不编造。 |
| passed | 对应实际的 passed 记录；未知写unknown，不编造。 |
| cost | 对应实际的 cost 记录；未知写unknown，不编造。 |
| currency | 对应实际的 currency 记录；未知写unknown，不编造。 |
| latency_ms | 对应实际的 latency_ms 记录；未知写unknown，不编造。 |
| evidence | 对应实际的 evidence 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 检查模型来源与许可证，列部署硬件或API条件，不默认下载巨大权重
- 在隔离测试配置中映射消息、工具返回、上下文与停止条件
- 先运行读取仓库与小补丁任务，记录实际命令结果、失败恢复与费用
- 交付配置差异和回滚说明；未经批准不修改全局客户端或提交代码

## 验收门槛

- 不能只改model字符串就称兼容
- 保留用户未提交修改
- 权重体量与资源要求需实查

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：文件读取成功而工具结果回传失败，应判工具协议不兼容而非模型答题失败。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
