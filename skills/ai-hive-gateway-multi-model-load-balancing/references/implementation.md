# 多模型负载均衡：专项实施卡

## 业务目标

按权重、并发、延迟、成功率和成本分配请求并限制单模型热点。

## 目标用户

负责线上 AI 应用、内容生产流水线、模型网关可靠性或媒体任务交付的架构师、SRE 和工程团队。

## 必须收集的证据

- 当前配置、端点、模型、调用量与失败样本。
- AI-HIVE 执行当天的模型列表、能力参数与价格快照。
- 3—10 个同输入、同时间、同验收口径的非生产样本。
- 每条样本的输入哈希、模型、参数、路由、taskId、状态、输出和实际成本。
- 回退开关、负责人、观察窗口和停止条件。

## 专项交付

路由策略、SLO 指标、故障注入用例、观测字段、告警阈值和恢复手册。

## 通过门槛

重点度量：负载偏差、P95、容量利用率。团队应在执行前填写具体阈值；没有阈值就只做探索，不得切入生产。

## 停止条件

不得用无限重试掩盖故障；异步任务超时后应续查原 taskId，避免重复提交和重复计费。 出现重复计费、孤儿任务、不可解释质量下降、未授权数据进入模型、预算越线或无法回退时，立即停止并保留现状。
