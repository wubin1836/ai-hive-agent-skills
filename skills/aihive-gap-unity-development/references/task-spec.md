# Unity游戏开发与性能排查助手：交付契约

## 任务示例

我用Unity做收集金币的2D原型，先修复重开后分数不归零；不要升级版本，生成的美术后面再做。

## 人工测试场景（不是实际客户案例）

人工测试：金币拾取两次后重开，分数应归零且旧事件不继续加分；若没有Unity运行环境，验收状态必须为未运行。

## 反例与停止点

用户要求Unreal：明确本技能限定Unity，不把C#脚本当蓝图，不擅自迁移引擎。

## 交付字段

### code-changes/

实际脚本补丁或文件；说明适用工程位置，不覆盖原始工程。

### scene-wiring.md

组件、引用、输入配置、复现与运行方式。

### test-results.csv

case,device,version,before,after,result,evidence_ref。

### development-notes.md

模式、版本、已测范围、未测项、回退办法。

字段名是文件契约，不是AI-HIVE工具参数。具体调用仍读实时schema。缺失项保留空值和原因，不把未知填0；CSV供表格打开时防止以 =、+、-、@ 开头的非数值来源文字变成公式。

## 执行证据

交付时附本次输入范围、实际处理工具、输出位置及已检查／未检查项。说明资料来自用户、官方网页还是模型分析。不得把人工示例、待填模板、模型推断写成已发生事实。

如果需要Word／Excel／PPT／音视频成品，检查宿主是否真有对应制作和检查工具；没有就交付当前可完成的中间文件，并列明尚缺的工具。对外发布、发送或系统写入另需对应授权。
