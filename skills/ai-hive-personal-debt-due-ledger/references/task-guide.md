# 专项执行参考

仅供参考，不构成投资建议，不承诺收益，不自动交易。

## 资料与交付约定

先确认任务地区/版本/时间范围及输出目录。证据表至少有 source_id、原文件页码或行号、原文、处理值、状态；状态使用 confirmed / uncertain / missing。来源身份与用户隐私不要在公开示例中泄露。

## 本项处理检查

- 同一债务跨文件按合同尾号和主体关联，疑似重复保留待确认
- 本金余额、已产生费用与本期应还分层，不互相加成重复总额
- 余额截止日统一，未知金额不填零，已还凭证与对应账期匹配

## 示例请求（虚构输入，仅说明调用方式）

仅示例，以下文件名和情境均为假设，不表示已存在真实数据：假设我已提供 示例_借款合同片段.pdf、示例_信用卡账单.pdf、示例_同日余额及还款.csv。请使用「个人负债与到期账单整理助手」，合并截至同一天的负债和到期账单，标出疑似重复债务及本期应还，先不安排偿还顺序。将结果写入我指定的本地目录，交付 personal-debt-ledger.xlsx、debt-due-dates.csv、debt-reconciliation-gaps.md。本例先离线处理；输入、工具或适用规则不足时先交缺口说明，不编造结果。需要联网更新来源先征得我同意，不登录账户、不代提交或付款。

## 交付验收

- 按实际产物检查文件结构，不能将 Markdown 改后缀冒充 DOCX/XLSX/PDF。
- 公式、金额、日期和图式编码使用脚本或可审查公式复算；模型生成的数字未经复算不能标为已核验。
- DOCX/PDF应渲染检查页码、字体与批注；XLSX回读表头、数据类型和公式；SVG/HTML实际预览。工具缺失则说明哪项视觉/内容验收未完成。
- 缺少输入时交缺件列表，不创建虚构的全套结果来通过核验；仅完成部分时清楚列出已交与未交。

## 专业与使用边界

不执行还款，不提供债务清零、征信修复或借新还旧方案；不替用户决定偿还顺序，存在困难时只整理与正规机构沟通所需资料。
