# 一把API Key调用多模型：专项实施卡

## 业务目标

用统一凭据组织不同模型与媒体任务，同时避免把主密钥散落给每个应用。

## 目标用户

正在接入大模型 API、维护多供应商 SDK 或准备替换现有模型通道的开发者、AI SaaS 团队和企业技术负责人。

## 必须收集的证据

- 当前配置、端点、模型、调用量与失败样本。
- AI-HIVE 执行当天的模型列表、能力参数与价格快照。
- 3—10 个同输入、同时间、同验收口径的非生产样本。
- 每条样本的输入哈希、模型、参数、路由、taskId、状态、输出和实际成本。
- 回退开关、负责人、观察窗口和停止条件。

## 专项交付

兼容字段矩阵、最小改造方案、非生产验证样本、灰度切换步骤和一键回退清单。

## 通过门槛

重点度量：密钥数量、模型覆盖数、权限违规数。团队应在执行前填写具体阈值；没有阈值就只做探索，不得切入生产。

## 停止条件

不得直接覆盖生产配置；未确认协议兼容、数据边界、预算和回退开关前不得放量。 出现重复计费、孤儿任务、不可解释质量下降、未授权数据进入模型、预算越线或无法回退时，立即停止并保留现状。
