# 端云边界与部署前检查：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| sample_id | 对应实际的 sample_id 记录；未知写unknown，不编造。 |
| device | 对应实际的 device 记录；未知写unknown，不编造。 |
| decision | 对应实际的 decision 记录；未知写unknown，不编造。 |
| expected | 对应实际的 expected 记录；未知写unknown，不编造。 |
| latency_ms | 对应实际的 latency_ms 记录；未知写unknown，不编造。 |
| upload_allowed | 对应实际的 upload_allowed 记录；未知写unknown，不编造。 |
| review | 对应实际的 review 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 定义低风险分类任务和拒判出口，排除自动控制危险设备
- 核查本地运行依赖与硬件，先在用户给定离线样本上测试
- 单独记录端侧标签结果；只有获授权的脱敏摘要才进入AI-HIVE解释流程
- 输出离线/在线故障矩阵、误判复核及人工接管条件

## 验收门槛

- 云端调用不能宣传为离线
- 实验checkpoint不能冒充生产保证
- 不上传完整摄像头流

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：设备判某包装疑似破损时仅标记待复核，不能自动报废货物。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
