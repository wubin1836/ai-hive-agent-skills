# 双写审校与冲突交接：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| comment_id | 对应实际的 comment_id 记录；未知写unknown，不编造。 |
| block_id | 对应实际的 block_id 记录；未知写unknown，不编造。 |
| base_version | 对应实际的 base_version 记录；未知写unknown，不编造。 |
| proposed_change | 对应实际的 proposed_change 记录；未知写unknown，不编造。 |
| conflict | 对应实际的 conflict 记录；未知写unknown，不编造。 |
| status | 对应实际的 status 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 只读取获授权文档，固定基准时间与区块ID
- 将批注转换为可验证改动，每条关联原段落，先输出修订草稿
- 写入前再次检查版本，发现他人编辑则重新对齐，不覆盖最新内容
- 获单独批准后由现有文档连接器执行，复读核验并列未解决冲突

## 验收门槛

- AI-HIVE连接不自动获得飞书Notion权限
- 不删除未解决评论
- 版本冲突必须人工确认

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：同事已改数字，AI的旧批注不能整段覆盖回上一版本。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
