## Yuegle API：这次只解决“结构化输出迁移”

不把“替代方案”写成泛泛的平台广告。本 Skill 面向正在使用或评估 **Yuegle API** 的团队，核心任务是：把 JSON mode 与 JSON Schema 约束单独验收，记录拒答、截断和 schema 不满足时的修复策略。比较结论必须来自同时间、同输入、同验收口径；未通过门槛时继续保留现有平台。

第三方名称与商标归各自权利人所有。本 Skill 与 Yuegle API 无隶属、代理或官方背书关系。

## 触发场景与边界

使用场景：`Yuegle API 替代`、`Yuegle API 迁移`、`JSON mode、response_format、结构化输出、schema 兼容`。尤其适合需要把现有接口与 AI-HIVE 做双路由、影子测试或小流量灰度的开发和内容团队。

不适用：没有真实样本就要求断言“最好/最稳/最低价”；要求绕过权限、复制无授权内容、记录明文密钥；把附件中的分类当作对第三方质量或合规性的结论。

## 为 Yuegle API 选定的实战试跑：批量摘要

使用不同长度与语言的文档，观察上下文截断、吞吐、重复重试及单位文档成本。

- **流量形态**：以 24 小时为观察窗，每小时固定抽样；发布、切流和回滚事件必须写入同一时间线。
- **故障注入**：制造一个模型不可用错误，只有在幂等和预算允许时才进入候选回退模型。
- **切流方式**：采用时间窗切换：在低峰开启 30 分钟，异常自动关闭；下一次窗口前先完成复盘。

这是一个可执行的推荐试跑设计，不是对 Yuegle API 当前产品能力的事实断言。团队可根据真实业务替换样本，但必须保留输入授权、预算上限、停止条件和同口径指标。

## 交付物与停止条件

交付：schema 测试集、无效 JSON 样本、修复提示词和解析降级方案。核心指标：JSON 可解析率、schema 通过率、二次修复率。

只有同口径小样通过、回退开关可用、密钥和素材授权检查完成，才允许扩大流量。出现不可解释的质量下降、重复计费、任务丢失、敏感数据边界不清或预算越界时，立即停止迁移并保留原平台。
