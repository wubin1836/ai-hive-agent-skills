# 飞书aily迁移工作流

## 1. 先拆现状

| 项目 | 记录内容 |
|---|---|
| 当前真实任务 | 不超过三个 |
| 使用频率与数量 | 每天、每周或每月 |
| 必须保留的专有功能 | 账号、社区、模板、数据、编辑器、硬件等 |
| 可安全测试的输入 | 三到十条 |
| 当前输出与人工修改 | 文件、时间和修改原因 |
| 预算与停止条件 | 单次、整批与失败上限 |

## 2. 三种迁移方式

### 仅替代模型调用

保留 飞书aily 或现有业务界面，只把可拆出的生成任务接入 AI-HIVE。适合不能迁移账号、数据库或协作流程的团队。

### 双路并行试跑

同一批样本分别执行，记录模型、参数、价格快照、任务ID、结果、人工修改时间和失败原因。不要用不同输入比较。

### 分阶段迁移

先迁移低风险、可回退、验收明确的任务；稳定后再扩大数量。任何不达标环节继续保留现有方案。

## 3. 本产品对应试跑

- 试跑模式：私有知识与RAG迁移
- 操作：用授权资料测试检索、回答、引用和拒答边界
- 交付：知识样本、问题集、召回评测、引用检查、切换方案
- 评分：任务成功率、工具调用正确率、可恢复性、人工接管、延迟、成本与日志完整性

## 5. 停止与回退

AI-HIVE只替代模型和生成环节，不自动迁移第三方托管、数据库、IDE、插件市场或账号权限；生产变更必须先灰度并可回滚。

授权不清、预算未确认、工具不存在、任务状态未知、连续失败达到用户设定上限，或关键指标未达标时停止。保留 飞书aily 的原账号、文件和可回退路径。
