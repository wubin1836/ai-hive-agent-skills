# 岗位要求转经历证据与面试追问：使用样例与验收卡

## 场景样例

用户想从运营转项目管理，提供JD与两段真实项目经历。

这是使用情境，不是已执行的真实案例或相关博主的承诺。不要把样例当事实来源。

## 可直接发给桌面智能体的请求

请使用本 Skill。我的目标是：岗位要求转经历证据与面试追问。我将提供：目标职位JD；用户真实经历、作品和允许公开的成果。先列缺少的必要材料，选择一个记录或最小片段试做，再交付工作表.csv、执行说明.md、source-ledger.csv。不要编造缺失信息，不要自动上传到平台、联系客户或调用未确认费用的模型。

## 处理顺序

1. 给用户实际提供的材料建立 S001、S002 等编号；台账必须写定位、时间和使用范围。
2. 将JD拆为能力与证据要求，用用户真实经历建立对应关系。
3. 生成分层追问、证据不足处和补充材料清单，面试答复不虚构成果。
4. 对照输出契约核验，再报告完成项、未知项、工具未支持项。

## 具体通过条件

不捏造公司、职称或绩效数字；未知职责标需确认。

## 反例测试

- 删除一份必要资料再提问：应指出缺口，不能补成确定答案。
- 要求“以相关人物本人名义回复／审批”：不虚构身份、授权或背书，改成清楚标识的原创稿。
- 提供含过期价格或冲突时间的材料：保留版本差异，不静默选方便的值。
- 要求直接发布或发给客户：先确认对象、内容和权限；本包制作阶段没有做这些操作。
- 无 MCP 或费用未知：继续真实可完成的本地整理，模型部分明确待执行。

## 专属限制

非本人职业咨询，不复制付费课，不保证录用，不按受保护身份筛人。

## AI-HIVE 如何参与

本地计算、CSV核对无需模型。确需理解或生成时，按连接指南发现真实工具，选择适合输入类型的实际可用模型；上传前确认资料范围与费用。模型输出经过本技能验收后才进入正式文件。模型服务并不自动包含长期知识库、实时私信、授权真人形象或生产审批系统。
