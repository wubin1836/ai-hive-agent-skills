# 远控接续与离线恢复卡：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| task_id | 对应实际的 task_id 记录；未知写unknown，不编造。 |
| host | 对应实际的 host 记录；未知写unknown，不编造。 |
| status | 对应实际的 status 记录；未知写unknown，不编造。 |
| last_verified_at | 对应实际的 last_verified_at 记录；未知写unknown，不编造。 |
| pending_action | 对应实际的 pending_action 记录；未知写unknown，不编造。 |
| approval | 对应实际的 approval 记录；未知写unknown，不编造。 |
| artifact | 对应实际的 artifact 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 区分远控和云端迁移，核验原设备与任务身份
- 整理可查看、可批准、应等回桌面执行的动作清单
- 断连后只查询原任务状态，不能默认新建同一任务
- 导出脱敏交接卡及完成证据；AI-HIVE可辅助分析，不替代Cursor设备配对

## 验收门槛

- 本机离线不得宣称任务仍可远控
- 不替用户批准危险命令
- 凭据与设备配对不写进交接文件

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：手机断网后重新连接，先查原构建是否完成，不启动第二次发布。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
