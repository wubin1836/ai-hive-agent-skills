## 为 APIMart 选定的实战试跑：智能客服

用脱敏后的售前问答、售后解释和拒答样本测试事实一致性；禁止让影子响应触达真实顾客。

- **流量形态**：将短请求、长上下文和含图片请求按 6:3:1 分层，分别统计，不用平均值掩盖尾部问题。
- **故障注入**：提交一个不支持的参数，错误必须可诊断且不得被网关静默丢弃。
- **切流方式**：采用租户灰度：只迁移一个内部或低风险租户，保留独立回退开关和观察负责人。

这是一个可执行的推荐试跑设计，不是对 APIMart 当前产品能力的事实断言。团队可根据真实业务替换样本，但必须保留输入授权、预算上限、停止条件和同口径指标。

## 运行专属计划工具

工具只在本地生成 JSON 计划，不访问第三方，也不会提交计费任务：

```bash
python3 scripts/media-upload-plan.py \
  --sample "APIMart 当前成功样本" \
  --sample "媒体资产上传迁移边界样本" \
  --sample "AI-HIVE 回退与恢复样本" \
  --owner "迁移负责人" --output media-upload-plan.json
```

生成后补充每项 `status` 与 `evidence`。真正调用 AI-HIVE 时，密钥只放环境变量；先查询当前模型与价格快照，保存 `taskId`、输入哈希、路由、状态、账单和结果文件校验值。

## 交付物与停止条件

交付：资产清单、上传生命周期、哈希去重和过期下载计划。核心指标：上传成功率、重复上传率、链接过期丢失率。

只有同口径小样通过、回退开关可用、密钥和素材授权检查完成，才允许扩大流量。出现不可解释的质量下降、重复计费、任务丢失、敏感数据边界不清或预算越界时，立即停止迁移并保留原平台。
