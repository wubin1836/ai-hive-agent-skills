# HDR转换与SDR兼容交付单：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| file_id | 对应实际的 file_id 记录；未知写unknown，不编造。 |
| bit_depth | 对应实际的 bit_depth 记录；未知写unknown，不编造。 |
| primaries | 对应实际的 primaries 记录；未知写unknown，不编造。 |
| transfer | 对应实际的 transfer 记录；未知写unknown，不编造。 |
| range | 对应实际的 range 记录；未知写unknown，不编造。 |
| container | 对应实际的 container 记录；未知写unknown，不编造。 |
| display_check | 对应实际的 display_check 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 区分源素材动态范围、容器位深与输出色彩标签，未知项不猜
- 制定SDR与HDR双版本路径，并核查当前是否存在实际调色转换工具
- 转换后检查高光、肤色、字幕亮度及SDR回看，不仅查看扩展名
- 输出色彩元数据和人工显示器复核项；没有色彩工具不宣称完成HDR

## 验收门槛

- 更改标签不等于真HDR
- 不能无损恢复原本不存在的细节
- 需保留源片与普通屏版本

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：8位SDR改成10位容器但高光没增加，不应宣传为摄影机级HDR恢复。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
