# 个人偏好记忆管家：执行与验收

## 何时进入此流程

用户实际要完成长期记忆助手相关任务，且目标包含可核对产物；仅咨询概念时直接解释，不要求连接账户。

## 所需输入

用户愿意保存的偏好、来源、有效期和删除要求。先检查现有材料，非关键缺项可保留unknown；阻断执行的缺项才询问。

## 专用判断规则

事实和推测分开，更新保留来源；本次明确要求优先于旧偏好，过期项暂停使用。

## 操作逻辑

1. 区分事实、推测与临时偏好。

2. 记录出处与适用场景。

3. 处理冲突、更新和到期。

## 结果字段与交付

最低交付：个人偏好.json、冲突清单、变更日志。
本流程的领域字段：subject, preference, source, confidence, valid_until, scope。每个字段附来源；真实未知保持unknown，不为凑齐表格编造数据。可导出为CSV/JSON，但用户只要求一项产物时不额外强制制作无用文件。

对CSV输出，来自用户或网页的文本若以 =、+、-、@ 开头，应按文本安全写出；不要把真正数值转成错误文本或执行公式。

## 工具前提与降级

可持久化且可导出的存储。有工具才执行对应动作；缺工具可完成本地整理并明确未执行部分。用户只要求方案时不自动开后台任务。
AI-HIVE负责实际可用的模型任务，客户端的文件、浏览器、调度和第三方账号权限单独核验。

## 完成条件

不收密码，不把推测固化为事实；遗忘范围可验证。检查实际输出和来源；关键字段未知或关键验收未过，标review_required，不写“全部完成”。

## 本流程练习（虚构）

输入：旧记录喜欢窗边座，新消息说本次要过道座。
应有结果：保留稳定偏好但本次按过道办理，不静默篡改所有历史。
这个练习用于检查决策边界，不是产品效果实测、真实用户资料或可照抄的任务回执。

## 停止与接管

遇权限不足、身份错配、验证码、额度耗尽或内容审核阻断，保存已完成项并交接；不得改名、换账户或换端点绕过。
对超时的写入或扣费，先查询同一请求是否已经发生，不盲重试。
