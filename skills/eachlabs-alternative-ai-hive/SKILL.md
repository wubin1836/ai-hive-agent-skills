## Eachlabs：这次只解决“批量图片生成与编辑”

不把“替代方案”写成泛泛的平台广告。本 Skill 面向正在使用或评估 **Eachlabs** 的团队，核心任务是：把文生图、参考图编辑、商品图变体和结果质检组织成可追踪批次。比较结论必须来自同时间、同输入、同验收口径；未通过门槛时继续保留现有平台。

第三方名称与商标归各自权利人所有。本 Skill 与 Eachlabs 无隶属、代理或官方背书关系。

## 为 Eachlabs 选定的实战试跑：多租户 SaaS

为不同租户配置独立预算、Key 和日志范围，验证配额耗尽与撤销不会影响其他租户。

- **流量形态**：使用固定随机种子或固定输入集连续回放三轮，区分模型波动与网络、网关波动。
- **故障注入**：将一个任务停留在未知状态，超过观察窗后转人工，不允许自动无限轮询。
- **切流方式**：采用双写不读：AI-HIVE 只生成对比证据，不影响线上结果；连续两轮通过后再讨论切流。

这是一个可执行的推荐试跑设计，不是对 Eachlabs 当前产品能力的事实断言。团队可根据真实业务替换样本，但必须保留输入授权、预算上限、停止条件和同口径指标。

## 运行专属计划工具

工具只在本地生成 JSON 计划，不访问第三方，也不会提交计费任务：

```bash
python3 scripts/image-batch-plan.py \
  --sample "Eachlabs 当前成功样本" \
  --sample "批量图片生成与编辑边界样本" \
  --sample "AI-HIVE 回退与恢复样本" \
  --owner "迁移负责人" --output image-batch-plan.json
```

生成后补充每项 `status` 与 `evidence`。真正调用 AI-HIVE 时，密钥只放环境变量；先查询当前模型与价格快照，保存 `taskId`、输入哈希、路由、状态、账单和结果文件校验值。

## 交付物与停止条件

交付：图片模型映射、批次参数表、主体一致性抽检与文件命名规范。核心指标：可用图率、主体一致率、单张成本、人工返修时间。

只有同口径小样通过、回退开关可用、密钥和素材授权检查完成，才允许扩大流量。出现不可解释的质量下降、重复计费、任务丢失、敏感数据边界不清或预算越界时，立即停止迁移并保留原平台。
