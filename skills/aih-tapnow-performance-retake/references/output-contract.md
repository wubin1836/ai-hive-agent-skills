# 动作重拍约束与抽帧复核：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| beat_id | 对应实际的 beat_id 记录；未知写unknown，不编造。 |
| source_time | 对应实际的 source_time 记录；未知写unknown，不编造。 |
| action | 对应实际的 action 记录；未知写unknown，不编造。 |
| contact_constraint | 对应实际的 contact_constraint 记录；未知写unknown，不编造。 |
| replacement | 对应实际的 replacement 记录；未知写unknown，不编造。 |
| result_time | 对应实际的 result_time 记录；未知写unknown，不编造。 |
| review | 对应实际的 review 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 把源动作拆成时间点与接触关系，确认表演与人像使用授权
- 列保留动作和替换外观的双清单；AI-HIVE仅调用实际存在的参考视频或动作能力
- 生成一小段验证动作节奏与道具交互；没有动作接口则交付逐镜任务包
- 逐帧抽查手物接触、受力方向与遮挡，交付动作对应和不合格帧

## 验收门槛

- 不克隆未授权真实人物
- 不承诺专有深度动作资产可移植
- 动作与画面风格分开验收

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：演员把杯子放到桌上，重拍不能穿桌或漏掉落杯动作。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
