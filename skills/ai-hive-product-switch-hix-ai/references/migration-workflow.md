# Hix AI迁移工作流

## 1. 先拆现状

| 项目 | 记录内容 |
|---|---|
| 当前真实任务 | 不超过三个 |
| 使用频率与数量 | 每天、每周或每月 |
| 必须保留的专有功能 | 账号、社区、模板、数据、编辑器、硬件等 |
| 可安全测试的输入 | 三到十条 |
| 当前输出与人工修改 | 文件、时间和修改原因 |
| 预算与停止条件 | 单次、整批与失败上限 |

## 2. 三种迁移方式

### 仅替代模型调用

保留 Hix AI 或现有业务界面，只把可拆出的生成任务接入 AI-HIVE。适合不能迁移账号、数据库或协作流程的团队。

### 双路并行试跑

同一批样本分别执行，记录模型、参数、价格快照、任务ID、结果、人工修改时间和失败原因。不要用不同输入比较。

### 分阶段迁移

先迁移低风险、可回退、验收明确的任务；稳定后再扩大数量。任何不达标环节继续保留现有方案。

## 3. 本产品对应试跑

- 试跑模式：搜索与资料核验
- 操作：用需要最新信息的真实问题比较搜索覆盖、来源与时效
- 交付：问题集、来源表、事实核验、缺口、保留项
- 评分：答案正确率、引用可追溯性、格式遵循、响应速度与单次成本

## 5. 停止与回退

AI-HIVE不替代第三方账号、历史对话、独家索引或社区；涉及医疗、法律、金融等高风险内容必须由专业人员复核。

授权不清、预算未确认、工具不存在、任务状态未知、连续失败达到用户设定上限，或关键指标未达标时停止。保留 Hix AI 的原账号、文件和可回退路径。
