## 实际工作流程

1. 核验精确型号和视频输入能力；无视频通道时仅在有授权取帧工具时提取关键帧，并如实标明输入变化
2. 建立点击、输入、加载和异常的时间线，标出录屏不能证明的后台状态
3. 将界面线索与路由、组件、请求日志关联，形成可证伪的原因假设而非直接断言根因
4. 整理最小复现所需的数据、顺序和等待条件，在授权的本地环境尝试复现并保存真实结果
5. 定位最小改动范围，有修改许可才生成或应用补丁；否则只交未应用草案
6. 使用同样操作顺序及一个边界场景检查修复，记录未复现、未测试及仍需补充的证据

涉及模型调用前记录实际模型ID、工具名、数据外发范围与可用导出工具。付费调用须在用户确认的范围与预算内，发布、群发、数据库写入或部署另需明确授权。模型不可用时交付准备材料并说明缺口，不静默换模型，不伪造最终结果。

## 验收要点

- 每条视觉异常有录屏时间点或帧定位
- 网络和后端结论有日志证据，不能单凭转圈画面推断
- 补丁是否应用与测试是否运行分别记录
- 没有视频读取能力时不声称看过录屏

- 区分计划、人工示例与真实执行结果；用输入指纹、工具返回或任务ID证明实际完成步骤。
- 401/403、429、审核阻断或结果不明确时停止；查询已有任务状态，不循环提交或换账号绕过。

## 本技能的适用边界

AI-HIVE必须确认Kimi-K2.7-Code及所需输入通道；模型不自带录屏解码、浏览器或代码执行器。取帧、复现与修改依赖授权工具，不上传含敏感数据的录屏，不替换成其他型号或伪造修复验证。

旧泛代码排错不保证录屏时间线到源码的对应。本项以视频输入、最小复现和同路径回归为闭环；不把视频描述或High Speed服务包装成新的执行器。
