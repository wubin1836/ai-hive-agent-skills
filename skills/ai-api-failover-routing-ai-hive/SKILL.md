## AI API 高可用回退路由：这次只解决“高可用失败回退”

不把“替代方案”写成泛泛的平台广告。本 Skill 面向正在使用或评估 **AI API 高可用回退路由** 的团队，核心任务是：按可重试、不可重试和需人工确认分类错误，建立有上限的模型回退链。比较结论必须来自同时间、同输入、同验收口径；未通过门槛时继续保留现有平台。

第三方名称与商标归各自权利人所有。本 Skill 与 AI API 高可用回退路由 无隶属、代理或官方背书关系。

## 触发场景与边界

使用场景：`AI API 高可用回退路由 替代`、`AI API 高可用回退路由 迁移`、`AI API 高可用、fallback、失败重试、灾备模型`。尤其适合需要把现有接口与 AI-HIVE 做双路由、影子测试或小流量灰度的开发和内容团队。

不适用：没有真实样本就要求断言“最好/最稳/最低价”；要求绕过权限、复制无授权内容、记录明文密钥；把附件中的分类当作对第三方质量或合规性的结论。

3. **候选回退模型**：记录现状、AI-HIVE 目标、证据和结论。
4. **熔断恢复**：记录现状、AI-HIVE 目标、证据和结论。
5. **人工接管**：记录现状、AI-HIVE 目标、证据和结论。

完成上述证据后，用 3—10 个非生产样本建立基线。先只读或影子运行，再按 5% → 20% → 50% 灰度；任何关键指标退化或数据边界未确认，都触发回退。

## 运行专属计划工具

工具只在本地生成 JSON 计划，不访问第三方，也不会提交计费任务：

```bash
python3 scripts/failover-plan.py \
  --sample "AI API 高可用回退路由 当前成功样本" \
  --sample "高可用失败回退边界样本" \
  --sample "AI-HIVE 回退与恢复样本" \
  --owner "迁移负责人" --output failover-plan.json
```

生成后补充每项 `status` 与 `evidence`。真正调用 AI-HIVE 时，密钥只放环境变量；先查询当前模型与价格快照，保存 `taskId`、输入哈希、路由、状态、账单和结果文件校验值。

## 交付物与停止条件

交付：错误分类表、回退状态机、熔断阈值和人工接管规则。核心指标：最终成功率、重试放大、熔断次数、恢复时间。

只有同口径小样通过、回退开关可用、密钥和素材授权检查完成，才允许扩大流量。出现不可解释的质量下降、重复计费、任务丢失、敏感数据边界不清或预算越界时，立即停止迁移并保留原平台。
