# 网页局部改版补丁与对照：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| annotation_id | 对应实际的 annotation_id 记录；未知写unknown，不编造。 |
| component | 对应实际的 component 记录；未知写unknown，不编造。 |
| requested_change | 对应实际的 requested_change 记录；未知写unknown，不编造。 |
| file_ref | 对应实际的 file_ref 记录；未知写unknown，不编造。 |
| desktop_review | 对应实际的 desktop_review 记录；未知写unknown，不编造。 |
| mobile_review | 对应实际的 mobile_review 记录；未知写unknown，不编造。 |
| status | 对应实际的 status 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 批注映射组件与可验证差异，区分全局和局部样式
- 在副本给最小补丁，未经批准不改支付登录或数据收集
- 用本地浏览器检查桌面手机和长文本状态
- 交付补丁前后截图未解决批注，不自动部署公网

## 验收门槛

- 截图位置不是真实DOM选择器
- 保持键盘焦点和文字对比
- 不覆盖未提交代码

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：放大购买按钮不能挤掉价格或改支付地址。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
