# 训练数据契约与奖励漏洞审查：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| rollout_id | 对应实际的 rollout_id 记录；未知写unknown，不编造。 |
| step_id | 对应实际的 step_id 记录；未知写unknown，不编造。 |
| environment | 对应实际的 environment 记录；未知写unknown，不编造。 |
| action_type | 对应实际的 action_type 记录；未知写unknown，不编造。 |
| outcome | 对应实际的 outcome 记录；未知写unknown，不编造。 |
| reward | 对应实际的 reward 记录；未知写unknown，不编造。 |
| split | 对应实际的 split 记录；未知写unknown，不编造。 |
| redacted | 对应实际的 redacted 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 用rollout ID连接多次模型调用，保存工具结果和环境版本但移除密钥
- 以任务结果定义奖励，检查是否鼓励越权、重复操作或只刷表面指标
- 拆分训练与验收任务，统计多段轨迹避免长rollout被多计权重
- 交付数据字典、失败轨迹和资源评估；训练部署需要额外工具、预算与授权

## 验收门槛

- 不上传客户对话训练除非获准
- 静态整理不宣称模型已提升
- 分割轨迹不能重复统计成功

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：一个任务产生十段消息不应比只用两段完成的任务得到十倍样本权重。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
