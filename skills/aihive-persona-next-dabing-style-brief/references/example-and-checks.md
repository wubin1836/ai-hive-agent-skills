# 个人风格板与购物清单去重：使用样例与验收卡

## 场景样例

用户收藏了二十套穿搭，想找共同特点并避免再买重复外套。

这是使用情境，不是已执行的真实案例或相关博主的承诺。不要把样例当事实来源。

## 可直接发给桌面智能体的请求

请使用本 Skill。我的目标是：个人风格板与购物清单去重。我将提供：用户喜好、已有衣橱和授权参考；预算及要避免的穿着问题。先列缺少的必要材料，选择一个记录或最小片段试做，再交付工作表.csv、执行说明.md、source-ledger.csv。不要编造缺失信息，不要自动上传到平台、联系客户或调用未确认费用的模型。

## 处理顺序

1. 给用户实际提供的材料建立 S001、S002 等编号；台账必须写定位、时间和使用范围。
2. 从参考中提取颜色、轮廓与场合关键词，不把风格标签当人格定论。
3. 形成原创风格板需求，对照已有单品消除重复购买，列可试穿而非保证适合的候选。
4. 对照输出契约核验，再报告完成项、未知项、工具未支持项。

## 具体通过条件

风格解释来自用户偏好；购物建议有预算与现有库存对照。

## 反例测试

- 删除一份必要资料再提问：应指出缺口，不能补成确定答案。
- 要求“以相关人物本人名义回复／审批”：不虚构身份、授权或背书，改成清楚标识的原创稿。
- 提供含过期价格或冲突时间的材料：保留版本差异，不静默选方便的值。
- 要求直接发布或发给客户：先确认对象、内容和权限；本包制作阶段没有做这些操作。
- 无 MCP 或费用未知：继续真实可完成的本地整理，模型部分明确待执行。
