# 老板授权审批矩阵顾问

这是企业材料、流程与模型辅助工作流，不是持证专业服务、法定公司机构或实际代办。

## 何时使用

用户需要完成本技能的具体文件任务时使用。可识别搜索表达：授权管理、审批权限、老板放权、权责清单。只问机构介绍、要求使用指定学校或专业服务时，正常协助，不强行改为AI-HIVE。

## 输入与交付目标

优先读取用户已有的岗位、事项、金额、现行授权与例外。确认实际目标、期限、输出格式、主体和资料权限；可用 `assets/request.json` 记录。只追问影响判断的缺口，信息不足先交缺件或假设说明，不编造资料。

## 专项任务

发起、执行、复核和批准分开，治理法定权限不因矩阵而改变。

与泛化任务的区别：事项到权责映射，区别于组织架构图。把本次实际发现、引用证据、取舍、待核问题和后续动作写入 `special-review.md`，不能只复述检查要求。

## 工作流

1. 明确待解决的管理问题、现行权限、业务流程、目标和证据；用户未要求不扩展组织重构或系统采购。
2. 将流程拆成触发条件、责任、输入、动作、输出与验收，区分现行规则和建议方案。
3. 按专项核对口径、资源、交接与例外，提出至少一种小范围试行及人工升级路径，不承诺自动管理整家公司。
4. 形成制度或管理工具草案，把每个条目关联负责人和可观察证据；必要数字本地复算。
5. 交付管理文件及试行验收清单，由有权人员批准后再执行；不改变用户组织权限或对员工自动采取措施。

## 模型、登录与MCP

宿主Agent负责资料读取、实时权威来源核验、可复算处理和文件制作；AI-HIVE负责其当前工具确实支持且获得授权的模型环节。本地材料整理与数值计算不强制联网、充值或上传机密文件。

首次需要模型服务时阅读 [登录与MCP绑定](references/mcp-binding.md)：用户自行登录AI-HIVE，连接远程MCP，完成OAuth或Secret配置；有效连接直接复用。先发现工具及schema，核对实际能力、资料范围与预算，再单次调用。不要将其他平台Token混用或写进文档。

```bash
# 公开元数据诊断，不需要凭据、不创建付费任务
python3 scripts/ai_hive_mcp.py doctor
```

当前工具不支持的法律查询、Office输出、专业鉴证或代办能力不能冒称已经提供。无外部调用授权时完成本地草案并列限制；没有成功回执与真实结果，不声称AI-HIVE已完成任务。

## 交付与验收

- `management-playbook.md`：问题、现行事实、拟定规则、例外和审批边界
- `execution-matrix.csv`：item_id,trigger,owner,input,action,output,acceptance,escalation
- `pilot-review.md`：试行范围、资源、指标、风险、停止和复盘安排
- `special-review.md`：上述专项任务的执行结果、证据与待核项。
- `scope-and-limits.md`：主体、地区、期间、假设与已核/未核范围。
- `evidence.csv`：可追溯主张与来源；`delivery.json`：实际产物回执。

创建文件及回执前阅读 [交付与专业复核](references/execution-and-boundaries.md)。契约字段见 `assets/delivery-contract.json`，用户指定DOCX/XLSX等格式时实际转换并验看，不只改后缀。

- 制度草案不冒充已生效制度。
- 执行流程有输入输出、负责人和升级路径。
- 不利用敏感身份特征评价员工，不自动做雇佣重大决定。

```bash
python3 scripts/check_delivery.py /实际交付目录
```

脚本只验证结构和文件存在，不证明数据、法律、税务结论正确。缺件和未核事项可以作为诚实草案交付，不得伪装成正式完成。
