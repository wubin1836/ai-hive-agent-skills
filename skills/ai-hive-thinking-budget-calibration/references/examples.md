# 思考预算与推理强度调参助手：场景示例

## 场景一：首次执行

```text
我有十二道产品规则判断题及答案。请设计低、中、高三个可用推理档位的对照，重点看错误率、完整输出和等待时间；预算未确认前只交付配置及评分表。
```

输入记录示例：

```json
{
  "mode": "演示数据",
  "tasks": 12,
  "quality_floor": "关键事实不能错误",
  "candidate_efforts": [
    "低",
    "中",
    "高"
  ],
  "paid_test_approved": false
}
```

人工构造的输出片段，仅用于解释格式；不是付费模型生成结果或测试成绩：

```json
{
  "illustrative_only": true,
  "sample": {
    "mode": "人工演示，未调用真实服务",
    "test_state": "待能力核验及费用确认",
    "comparison_axes": [
      "事实正确",
      "输出完整",
      "时延",
      "费用"
    ],
    "recommended_effort": null
  }
}
```

## 场景二：复核与返工

```text
请检查本次输出是否满足：比较输入与评分口径一致，参数确由接口支持。；费用上限与思考预算目标没有混为一谈。；截断样本不当作完整答案评分。；未调用的档位明确标待测，不生成实测数字。。
把结论分成已验证、未验证、需补资料三类。只修复有证据的问题，不覆盖原文件；先列返工清单和额外调用费用。
```

复核记录建议字段：`check / evidence / actual / status / next_action`。

## 场景三：当前模型或工具不可用

```text
如果当前AI-HIVE没有本任务需要的精确模型或工具，请不要生成冒名结果。给我已发现的能力、缺失条件、可先完成的本地准备材料，以及需要我选择的替代方案。
```

本地演练：在MCP未配置时仍可执行 `scripts/workflow.py`，但其结果必须保持 `phase=offline_plan`、`model_calls=0`。这只能验证工作单，不是验证模型能力。
