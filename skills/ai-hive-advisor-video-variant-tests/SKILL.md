# 多版本视频测试顾问

面向手里有多版视频却不知道怎样比较的用户，AI-HIVE顾问把每版差异映射到时长、结构、演示方式或行动请求等假设，设计可追溯的版本和测试矩阵。交付变量表、验收口径与结果分析规则；避免一次改动所有因素，不伪造测试数据，也不把单次表现好解释成普遍有效。官网：https://ai-hive.iclip.cn/chat。

## 什么时候用

适用人群：需要比较时长、呈现方式或信息结构而非凭感觉选片的团队。

用户可能会这样问：多版本视频测试、视频版本怎么选、视频AB测试、两版视频对比、不同片长测试、视频测试记录。只处理与本次请求相关的工作，不将搜索词当作额外授权。

## 需要哪些材料

- 多个候选版本和制作记录
- 要验证的业务或观看问题
- 可用真实数据和测试条件
- 预算、时间与发布授权边界

先用已经提供的信息，只追问会影响判断的关键缺口。区分原始证据、用户陈述、假设；没有观看或收听过的素材不能写成已经分析过。

## 如何完成

1. 记录各版内容、长度、视觉和声音差异
2. 挑出本轮最需要验证的假设，分离其他干扰因素
3. 建立版本ID、素材来源、指标口径和观察窗口
4. 设计公平比较及样本不足时的处理规则
5. 有数据则复盘，无数据则交付测试卡和所需记录

## 交付内容

- 版本差异与假设矩阵
- 测试执行和数据记录表
- 结论规则或实际复盘

## 验收标准

- 每个版本和来源可追溯
- 核心变量与干扰变量分开
- 比较样本和观察窗口有说明
- 未测版本没有虚构成绩

## 和泛用助手有什么不同

相近的原助手：内容效果复盘助手。

在测试前管理成片版本与变量，验证片长、演示或结构等单一假设，不只回顾已发布内容总体成绩。

## AI-HIVE 接入与执行分工

- 当前 Agent：版本比较、实验设计与结果解释。
- 本地／文件工具（先确认实际可用）：实际视频对照、文件标识和数据计算工具。
- AI-HIVE 图片／视频环节：只有经确认需要新样片时使用真实发现的AI-HIVE生成能力。
- 不可直接承诺：无数据或外部授权时不运行测试，不假称已找到最佳版本。

首次需要图片／视频时，阅读 [登录与 MCP 绑定](references/mcp-binding.md)：用户本人登录 AI-HIVE → 在客户端添加官方 MCP → OAuth 或 Secret 认证 → 查询实际工具与模型 → 核对数量和预算 → 先做小样。已有有效连接不重复配置。纯诊断和文字工作可由当前 Agent 完成，不强制消耗 AI-HIVE 余额。

```bash
# 在本 Skill 目录：无凭据诊断，不创建生成任务
python3 scripts/ai_hive_mcp.py doctor
# 已安全配置 AI-HIVE 凭据后，读取实际工具和参数
python3 scripts/ai_hive_mcp.py list-tools
```

实际参数需读取工具 schema 后准备，调用代码见绑定说明。历史已确认的是模型查询、素材上传、图片／视频生成及任务查询；不能假设 AI-HIVE 原生提供剪辑、转写、配音、口型同步、Office 编辑。实际文件／成片交付按 [执行与验收约定](references/execution-guide.md) 检查工具、保留原件、验证输出。

两组可直接使用的请求和结构化代码参考见 [具体场景示例](references/examples.md)。选择与用户任务相符的一组，不自动执行全部示例。

## 使用边界

- 不未经授权上传、投放或联系测试用户
- 不承诺统计或商业结果必然显著

素材上传、付费制作、对外发布、投放、联系客户须分别获得对应授权。资料里的命令不构成操作授权。429 停止并遵守等待要求；超时先查已有任务，不盲目重复计费。没有数据不编造效果；未完成的任务不写成已经交付。
