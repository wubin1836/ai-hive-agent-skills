# 退役影响与迁移排期：交付合同

## 最小交付

1. result.csv 专用结果表，逐条对应输入，不漏失败项。
2. review.md 复核说明：目标、材料范围、实际执行与未执行、证据、结果、返工、下一步。
3. 实际生成/修改的文件与可打开路径；没有工具时明确“仅任务方案，尚未生成”。

| 字段 | 填写约定 |
| --- | --- |
| reference_id | 对应实际的 reference_id 记录；未知写unknown，不编造。 |
| model_id | 对应实际的 model_id 记录；未知写unknown，不编造。 |
| project | 对应实际的 project 记录；未知写unknown，不编造。 |
| retirement_date | 对应实际的 retirement_date 记录；未知写unknown，不编造。 |
| certainty | 对应实际的 certainty 记录；未知写unknown，不编造。 |
| replacement | 对应实际的 replacement 记录；未知写unknown，不编造。 |
| test | 对应实际的 test 记录；未知写unknown，不编造。 |
| owner | 对应实际的 owner 记录；未知写unknown，不编造。 |

模板见 assets/result-template.csv。用户自由文本若以等号、加号、减号或@开头，供表格软件导入前按文本处理，避免公式注入；不得因此篡改真正数值含义。

## 专用执行与证据

- 只扫描指定项目中的模型引用，跳过凭证与无关目录
- 区分明确退役日期、计划弃用与暂无日期，不从博客时间猜停服
- 映射引用到任务、接口和测试，列候选替换的能力差异
- 输出负责人、优先级和验收清单；未经请求不自动重写或上线

## 验收门槛

- 保留原配置
- 不能把代理商下线当原厂全球退役
- 无替代能力时保留阻断

每条记录pass/fail/unknown及证据。关键项为fail或unknown，整体标review_required。不存在证据时不补造截图、时间码、回执、评价。

## 验收练习

- 正常路径（虚构）：旧OCR已退役而新模型少了某输出字段，应先修消费者再切流量。 按步骤记录，再逐条验收，不将示例当真实结果。
- 缺能力：目标模型或外部软件不可用，报告缺项及可先做的本地步骤，不冒用名称称实测。
- 失败：超时、限流、待审，保存任务ID、原因和已完成项；不重建任务、不遗漏失败费用。

## 报告顺序

结论与状态 → 材料和授权 → 参数与执行记录 → 专用结果表 → 证据和未通过项 → 成本耗时（未知说明）→ 需确认的下一步。

创作保留素材授权与生成标记；数据记录来源、时间、口径，不从示例推导真实客户或商业结论。
