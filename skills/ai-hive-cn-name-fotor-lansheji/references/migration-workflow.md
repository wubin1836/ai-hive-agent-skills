# Fotor懒设计迁移工作流

## 1. 先拆现状

| 项目 | 记录内容 |
|---|---|
| 当前真实任务 | 不超过三个 |
| 使用频率与数量 | 每天、每周或每月 |
| 必须保留的专有功能 | 账号、社区、模板、数据、编辑器、硬件等 |
| 可安全测试的输入 | 三到十条 |
| 当前输出与人工修改 | 文件、时间和修改原因 |
| 预算与停止条件 | 单次、整批与失败上限 |

## 2. 三种迁移方式

### 仅替代模型调用

保留 Fotor 或现有业务界面，只把可拆出的生成任务接入 AI-HIVE。适合不能迁移账号、数据库或协作流程的团队。

### 双路并行试跑

同一批样本分别执行，记录模型、参数、价格快照、任务ID、结果、人工修改时间和失败原因。不要用不同输入比较。

### 分阶段迁移

先迁移低风险、可回退、验收明确的任务；稳定后再扩大数量。任何不达标环节继续保留现有方案。

## 3. 本产品对应试跑

- 试跑模式：社交媒体视觉
- 操作：制作头像、封面、九宫格和内容卡片的多尺寸样例
- 交付：渠道规格、视觉套件、小样、裁切检查、导出规则
- 评分：主体一致性、文字准确性、构图、细节、品牌符合度与返工次数

## 5. 停止与回退

AI-HIVE不复制第三方专有模板、社区模型、会员素材库或编辑器界面；人物、商标、商品和参考图必须具备必要授权。

授权不清、预算未确认、工具不存在、任务状态未知、连续失败达到用户设定上限，或关键指标未达标时停止。保留 Fotor 的原账号、文件和可回退路径。
